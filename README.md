## Understanding Django Middleware

Middleware is a layer between the user's request and Django's view.

When a user sends a request to a Django application, the request does not necessarily go directly to the view.

It passes through Django's middleware first.

A simplified flow looks like this:

```text
User
  |
  v
Request
  |
  v
Middleware
  |
  v
URL Resolver
  |
  v
View
  |
  v
Response
  |
  v
Middleware
  |
  v
User
```

This makes middleware useful when you want to perform some operation before or after a view is executed.

## BlockedIpMiddleware

The second middleware demonstrates how a request can be blocked based on the client's IP address.

Example:

```python
class BlockedIpMiddleware(MiddlewareMixin):

    BLOCKED_IPS = ["127.0.0.1"]

    def process_request(self, request):
        ip = request.META.get("REMOTE_ADDR")

        if ip in self.BLOCKED_IPS:
            return HttpResponse("Your IP is blocked.")
```

The middleware gets the client's IP address using:

```python
request.META.get("REMOTE_ADDR")
```

It then checks whether the IP exists inside the blocked IP list.

If the IP is blocked, the middleware returns an `HttpResponse` immediately.

This means the request does not continue to the view.

## How `process_request()` Works

`process_request()` runs when Django receives a request and the request is passing through middleware.

For example:

```python
def process_request(self, request):
    print(request.method)
```

You can use the request object to access information such as:

```python
request.method
request.path
request.META
```

In this project, `process_request()` is used for request logging and IP checking.

---

## How `process_response()` Works

`process_response()` works with the response generated by Django.

Example:

```python
def process_response(self, request, response):
    print(response.status_code)
    return response
```

The response object contains information about the response that will be sent back to the client.

For example:

```python
response.status_code
```

can tell us whether the request was successful.

A successful response commonly has:

```text
200
```

## MiddlewareMixin

This project uses Django's:

```python
from django.utils.deprecation import MiddlewareMixin
```

and middleware classes inherit from:

```python
MiddlewareMixin
```

Example:

```python
class SimpleMiddleware(MiddlewareMixin):
    ...
```

`MiddlewareMixin` provides a convenient way to implement middleware using methods such as:

```text
process_request()
process_response()
```

This makes it easier for beginners to understand how custom middleware works.

## Adding Middleware to Django

After creating middleware, it needs to be added to the `MIDDLEWARE` list in:

```text
settings.py
```

For example:

```python
MIDDLEWARE = [
    # Django middleware...

    "blog.middleware.SimpleMiddleware",
    "blog.middleware.BlockedIpMiddleware",
]
```

The middleware path depends on the name of your Django app and middleware file.

---

## Middleware Order

Middleware is executed in the order in which it appears in the `MIDDLEWARE` list.

For example:

```python
MIDDLEWARE = [
    "blog.middleware.SimpleMiddleware",
    "blog.middleware.BlockedIpMiddleware",
]
```

Here, `SimpleMiddleware` appears before `BlockedIpMiddleware`.

This is important because middleware can affect how requests and responses are processed.

Understanding middleware order becomes especially important in larger Django applications where multiple middleware layers are working together.
